# samtu

بزرگ‌ترین بستهٔ ممکن که از مسیر تا یک مقصد رد می‌شود را با جست‌وجوی دودویی و `ping -M do` پیدا می‌کند و اگر بخواهی همان MTU را روی اینترفیس ست می‌کند.

به درد وقتی می‌خورد که یک تانل یا لینک PPPoE بسته‌های بزرگ را بی‌صدا می‌اندازد: صفحه‌ها نصفه لود می‌شوند، SSH روی خطوط طولانی هنگ می‌کند، دانلود وسط کار می‌ایستد. این همان مشکل path MTU است و این ابزار عددش را می‌دهد.

## استفاده

<div dir="ltr">

```sh
git clone https://github.com/sarabbafrani/samtu.git
cd samtu
chmod +x mtu.sh
./mtu.sh
```

```
destination 8.8.8.8 over eth0, current MTU 1500, 4 packets per probe

  ok      1038
  dropped 1269
  ok      1153
  ...

largest working MTU: 1420
run again with -a to set it, or: sudo ip link set dev eth0 mtu 1420
```

</div>

تا وقتی `-a` ندهی هیچ چیزی روی سیستم عوض نمی‌شود.

## گزینه‌ها

<div dir="ltr">

```
-d HOST   مقصد، آدرس یا نام (پیش‌فرض 8.8.8.8)
-i IFACE  اینترفیسی که سقف از آن خوانده و روی آن ست می‌شود
-c N      تعداد بسته در هر آزمایش (پیش‌فرض ۴)
-o N      سربار تانل که کم می‌شود، به بایت
-w N      تایم‌اوت هر آزمایش به ثانیه (پیش‌فرض ۲)
-l N      کمترین اندازه‌ای که بررسی می‌شود (پیش‌فرض ۵۷۶ و برای IPv6 برابر ۱۲۸۰)
-a        همان MTU را روی اینترفیس ست کن
-q        فقط خود عدد را چاپ کن، برای استفاده در اسکریپت
```

```sh
./mtu.sh -q
1420

./mtu.sh -d example.com -o 80 -a
```

</div>

مقصد IPv6 از روی خود آدرس تشخیص داده می‌شود و به‌جای `ping6` که منسوخ شده از `ping -6` با هدر ۴۸ بایتی استفاده می‌کند.

## روش جست‌وجو

سقف، MTU فعلی همان اینترفیس است نه عدد ثابت ۱۵۰۰، پس هم jumbo frame و هم تانل درست مدیریت می‌شود. هر آزمایش `اندازه - ۲۸ - سربار` بایت با بیت don't fragment می‌فرستد و اندازه‌ای موفق حساب می‌شود که همهٔ بسته‌ها برگردند. چون جست‌وجو دودویی است، یک بازهٔ ۱۵۰۰ بایتی حدود ده آزمایش خرج برمی‌دارد نه صدها تا.

قبل از شروع بررسی می‌کند که کمترین اندازه اصلاً رد می‌شود یا نه، تا مقصدی که ICMP را جواب نمی‌دهد با پیام روشن رد شود نه با گزارش MTU صفر.

## پیش‌نیازها

`ping` از iputils و `ip` از iproute2. ست کردن MTU روت می‌خواهد و اسکریپت فقط وقتی `-a` بدهی سراغش می‌رود.
